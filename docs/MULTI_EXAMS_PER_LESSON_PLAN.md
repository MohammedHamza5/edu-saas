# خطة التطوير المعمارية: دعم اختبارات متعددة للمحاضرة الواحدة (Multi-Exams Per Lesson)
> **تاريخ التوثيق:** 2026-10-09  
> **الحالة:** معتمد للتنفيذ البرمجي  
> **الهدف:** الانتقال من علاقة 1-to-1 (اختبار واحد فقط للمحاضرة) إلى علاقة 1-to-Many (اختباران أو أكثر للمحاضرة مثل: كويز فهم، واجب، اختبار إتقان) مع ضمان **عدم كسر أي بيانات سابقة (100% Backward Compatibility)** وعدم حدوث أي انهيار أمني أو برمجي.

---

## 1. القرارات المعمارية وقواعد العمل المحسومة
1. **قاعدة البيانات:** جدول وسيط نظامي علائقي `public.lesson_exams` يربط `(group_id, content_id, exam_id)` مع الحفاظ التام على العمود التوافقي `associated_exam_id` في `content_groups` و `content` ليشير دائماً تلقائياً للاختبار الأساسي الأول منعاً لانهيار أي شاشة قديمة أو استعلام سابق.
2. **شرط التعاقب وفتح المحاضرة التالية (Sequential Learning Gatekeeper):**
   - لكل اختبار مرفق بالمحاضرة خيار `is_required` (إلزامي لاجتياز المحاضرة أم تدريبي/اختياري).
   - لا تفتح المحاضرة التالية إلا باجتياز الطالب **لكافة الاختبارات الإلزامية** المرفقة بالمحاضرة بالإضافة لمشاهدة الفيديو.
   - الاختبارات الاختيارية لا تعطل تقدم الطالب.
3. **تجربة واجهة الطالب في مشغل الفيديو (Student UX):**
   - عرض قائمة كروت عمودية أنيقة لكل اختبار يوضح:
     - عنوان الاختبار ونوعه (إلزامي 🔒 / اختياري 🎯).
     - حالة الطالب (مكتمل وناجح بـ XX% / يحتاج إعادة / متاح للبدء / مغلق بانتظار مشاهدة الفيديو).
     - زر الإجراء المباشر (بدء الاختبار / إعادة المحاولة / مراجعة الإجابات).
     - مؤشر تقدم إجمالي للمحاضرة (مثال: "أكملت 1 من 2 اختبارات إلزامية").
4. **تجربة واجهة المدرس في لوحة التحكم ومحرر المحاضرة:**
   - استبدال الـ Dropdown المفرد بقسم إدارة اختبارات المحاضرة (Multi-Quiz Manager):
     - قائمة كروت الاختبارات المرفقة مع إمكانية التبديل بنقرة زر بين (إلزامي / اختياري) وزر حذف.
     - زر `[+ إضافة اختبار للمحاضرة]` لاختيار كويز موجود أو إنشاء كويز فوري.
   - في صفحة الاختبارات العامة: ربط اختبار بمحاضرة يقوم بإضافته إليها في `lesson_exams` دون مسح الاختبارات الأخرى المرتبطة بنفس المحاضرة.
