## ثانيًا: القرارات المعمارية المقفولة 🔒 (من memory/decisions.md)

- **State Management = Cubit (flutter_bloc)** وليس Riverpod — معمارية غير مربوطة بالأداة: `UI → Cubit → Repository → DataSource`، ويمكن التبديل لاحقًا دون كسر الطبقات.
- **Backend = Supabase** (Auth + PostgreSQL/RLS + Storage + Edge Functions).
- **Video = Bunny Stream** — شبه نهائي: ينتظر اختبارًا عمليًا فعليًا قبل القفل 100%.
- **Push = FCM** (Web/Android/iOS) — توصيل فقط؛ الـDB هو مصدر الحقيقة.
- **Web Host = Cloudflare Pages**.
- **Secrets**: لا Service Role Key ولا أي Secret داخل Flutter/Git أبدًا — فقط Edge Function Secrets.
- **أدوار V1**: Teacher / Student / Parent فقط.
- **لا حذف نهائي للبيانات الأكاديمية** — status = archived/suspended.
- **بيئتان منفصلتان**: Development / Production.
- **لا PostgreSQL ENUM صارم** — text + تحقق على مستوى DB.

## خامسًا: قاعدة التحديث

أي قرار تنفيذي جديد غير مغطى بالوثيقة → يُسجَّل هنا بتاريخه والسياق والبدائل المرفوضة والنتيجة. **لا يُعدَّل بند مقفول 🔒 إلا بقرار "مراجعة" صريح موثّق في هذا الملف.**

### القرارات التنفيذية والأمنية المسجلة
- **2026-09-08 — تحصين التزامن وتعدد النوافذ (Multi-Tab Concurrency Defense):**
  - **السياق:** محاولة الطالب استغلال فتح التطبيق في عدة ألسنة تبويب لإنشاء محاولات متوازية للامتحان أو إحداث تضارب أثناء التسليم (Split-Brain) أو تجميد المؤقت في الخلفية.
  - **القرار المحسوم:**
    1. محرك قاعدة البيانات هو الحاسم النهائي عبر الفهرس الجزئي الفريد `one_active_attempt_per_student` على `exam_attempts (exam_id, student_id) WHERE status = 'in_progress'` لمنع وجود محاولتين متزامنتين فيزيائيًا.
    2. التسليم يتم كـ Atomic Transaction ذرية ومغلقة ومحصنة بـ Idempotency، وأي تسليم ثانٍ يُرفض فورًا بـ `EXAM_ALREADY_SUBMITTED`.
    3. انتهاء الوقت يُحسب حصريًا على السيرفر ولا علاقة له بساعة المتصفح أو تجميد التاب.
    4. تفعيل قنوات مزامنة الواجهة (Web BroadcastChannel) كطبقة UX إضافية لتحذير المستخدم وتعطيل النوافذ القديمة.

- **2026-10-21 — إنجاز واعتماد المهمة 16 (QA / Production Hardening Certification):**
  - **السياق:** التدقيق الأمني النهائي للنسخة الأولى V1 قبل النشر على Cloudflare Pages والتحقق من صرامة عزل المستأجرين والأدوار.
  - **القرار المحسوم:**
    1. اعتماد جناح مصفوفة الهجوم الأمني الـ 11 (`test/security/attack_matrix_12_5_test.dart`) كبوابة إلزامية لـ CI/CD (اجتياز 100%).
    2. اعتماد جناح اختبارات الدخان للرحلات الحرجة (`test/smoke/critical_flows_smoke_test.dart`) لتأكيد سلامة تدفق البيانات بين المدرس والطالب وولي الأمر.
    3. خلو شجرة الكود بالكامل من أي مفاتيح سرية (Service Role Keys) مع نجاح البناء الإنتاجي للويب (`flutter build web --release`).

- **2026-10-21 — ترسانة الطالب الأكاديمية الاحترافية (Student Super-Arsenal: Bluebook Matrix, Question Vault & Anki Drill):**
  - **السياق:** رغبة الطالب في تجربة اختبارية عالمية (تحاكي College Board Bluebook) مع أدوات دراسية ذكية للاسترجاع النشط والتكرار المتباعد (Spaced Repetition).
  - **القرار المحسوم:**
    1. **Personal Question Vault:** حفظ وتخزين الأسئلة المفضلة/الصعبة مع ملاحظات شخصية خاصة بالطالب (Encrypted/Cached Local Vault) دون إثقال السيرفر بعمليات حفظ عشوائية.
    2. **Anki-Style Active Recall Drill:** نظام تدريب كروت استرجاع نشط منفصل؛ يختار الطالب الإجابة، يرى النتيجة فوراً، ثم يقيم الصعوبة بـ 3 خيارات مباشرة (سهل 🟢 متقن / متوسط 🟡 يراجع لاحقاً / صعب 🔴 يُعاد إدراجه فوراً في نهاية طابور نفس الجلسة ليتكرر حتى الإتقان).
    3. **Bluebook Review Grid Matrix:** نافذة سفلية تعرض شبكة مرئية لجميع أسئلة الامتحان بحالاتها الثلاث (تمت الإجابة / غير مجاب / مميز للمراجعة 🚩) مع إمكانية القفز السريع لأي سؤال، وتحذير أمني عند محاولة التسليم مع وجود أسئلة فارغة.
    4. **التوافق المعماري والتعريب 100%:** الالتزام الصارم بـ Clean Architecture و Cubit وعدم تجاوز أي ملف لـ 150-200 سطر، مع تغطية شاملة باختبارات Unit و Responsive متعددة الشاشات (185/185 اختبار ناجح بنسبة 100%).
